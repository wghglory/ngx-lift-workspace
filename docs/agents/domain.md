# Domain docs

Use a single-context layout: root GLOSSARY.md and docs/adr/.

Before exploring domain behavior, read GLOSSARY.md and relevant ADRs. If absent, proceed silently. Create domain
documentation lazily when domain-modeling resolves terms or decisions.

Use glossary terms consistently in issues, proposals, code, and tests. Surface conflicts with existing ADRs explicitly,
identifying the ADR and explaining the proposed departure.
